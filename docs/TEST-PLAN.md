# OPTEX — Test Plan

**Date:** 2026-08-13 · Written against `docs/FEATURE-STATUS.md`'s 73 ✅-done features.

Before this pass: 3 API test files (34 Jest+supertest e2e tests) and 4 Playwright files (10 tests) — covering checkout's signed-out boundary, cart guest-merge, cart empty states, the appointments auth gate, and SPEC-06 order cancellation end to end. Everything else "done" per FEATURE-STATUS was unverified by anything automated. `apps/admin` has zero tests, unchanged by this pass.

## Method

Risk-tiered, not feature-by-feature: 73 items is too many to test with equal weight, and most of the risk concentrates in a handful of areas — money, auth, data isolation, and concurrency. Tier 1 gaps were closed first; Tier 2+ are scoped but not yet built, listed as backlog below rather than silently deferred.

## Tier 3 — Medium (admin panel): zero coverage, unchanged by this pass

`apps/admin` has no test infrastructure at all — no Playwright config, no fixtures. Before writing admin tests, the panel needs its own Playwright project (mirroring `apps/web`'s, pointed at :1113) and an authenticated-admin fixture. Candidates once that exists, in order:

1. Orders — status transitions, the direct-cancel flow (SPEC-06 R3), the paid-order acknowledgement dialog
2. Products — CRUD + image upload
3. Payments — reconcile, the "Needs attention" tab
4. Reviews moderation

## Tier 4 — Low: intentionally not tested

Static marketing sections, content pages, policy pages — no logic to regress. Per this plan's "what to cover" principle, testing them would be padding, not coverage.

## Backlog note on scope

This pass covered every Tier 1 gap end to end but did not attempt Tier 2/3 — 73 ✅ features is a large surface, and the risk-weighted subset (money, auth, data isolation, concurrency) captured the highest-value, highest-likelihood-of-silent-failure areas first. Tier 2 is the natural next pass.

# OPTEX — Test Plan

**Date:** 2026-08-13 · Written against `docs/FEATURE-STATUS.md`'s 73 ✅-done features.

Starting point: 3 API test files (34 Jest+supertest e2e tests) and 4 Playwright files (10 tests) — covering checkout's signed-out boundary, cart guest-merge, cart empty states, the appointments auth gate, and SPEC-06 order cancellation end to end. Everything else "done" per FEATURE-STATUS was unverified by anything automated. Five passes later: 8 API test files (96 tests), 5 `apps/web` Playwright files (13 tests), and `apps/admin`'s first-ever test infrastructure plus 5 Playwright files (19 tests) — Tier 3 fully closed.

## Method

Risk-tiered, not feature-by-feature: 73 items is too many to test with equal weight, and most of the risk concentrates in a handful of areas — money, auth, data isolation, and concurrency. Tier 1 gaps were closed first; Tier 2+ are scoped but not yet built, listed as backlog below rather than silently deferred.

## Tier 3 — Medium (admin panel): closed

`apps/admin` had no test infrastructure at all before this pass — no Playwright config, no fixtures, nothing. Built:

- **`playwright.config.ts`** mirroring `apps/web`'s (production build, not `next dev`; same reasoning — per-route dev compilation is exactly the flakiness a smoke suite shouldn't have to work around).
- **`global-setup.ts`** — every route except `/login` is gated by `middleware.ts` on `app_metadata.role === 'super_admin'`, checked via a real Supabase SSR **cookie** session, not a bearer token. A hand-minted JWT (the shape the API's Jest fixtures use) would not satisfy it. Setup creates a throwaway admin account, logs in through the actual `/login` form once, and saves the resulting cookie session as `storageState` for every test to reuse.
- **`global-teardown.ts`** — deletes every `@optex-test.local` auth user after the run. Found and fixed a real leak while writing it: `listUsers()` paginates at 50/page by default, and an unpaginated call only ever cleans the first page — 144 stale accounts had accumulated across this session's Jest runs before this was caught. The underlying pattern is systemic, not a one-off: **every Jest fixture file in `apps/api/test/` deletes its `customers` row on cleanup but never the linked `auth.users` row** — confirmed by running the full 96-test Jest suite once and watching exactly 25 stray accounts appear immediately after. Same bug, independently, in `apps/web/e2e/checkout-authenticated.spec.ts`. Cleaned the stray data each time it was found; the actual code fix (delete the auth user, not just the customer, in every affected `afterAll`) is backlog — it touches ~7 files outside this pass's scope (Tier 3, `apps/admin`), not a one-line change.

## Tier 4 — Low: intentionally not tested

Static marketing sections, content pages, policy pages — no logic to regress. Per this plan's "what to cover" principle, testing them would be padding, not coverage.

## Backlog note on scope

Tier 1, Tier 2 and Tier 3 are all closed end to end. What's left is no longer test coverage — it's product and hygiene decisions this pass surfaced but deliberately didn't act on: the full paid-checkout path (blocked on payment-provider sandbox credentials or mocking, not effort), the product-image-upload UI gap (wire it up or drop the endpoint), and the auth-user cleanup leak across `apps/api/test/`'s Jest fixtures and `apps/web/e2e/checkout-authenticated.spec.ts` (confirmed systemic, ~7 files, not a one-line fix).

# OPTEX Backend

Supabase (Postgres + Auth + Storage) + Node.js / Next.js route handlers per [docs/AUDIT.md §5-§6](../docs/AUDIT.md). Bound by **OPTEX-SOW-2025-001-KE v3.0** (Kenya).

Currently this folder holds the **Supabase definition** (schema, RLS, storage, seed). The Node/Express service is not yet scaffolded.

## Layout

```
Backend/
└─ supabase/
   ├─ config.toml                  Supabase CLI project config
   ├─ migrations/
   │  ├─ 0001_init_schema.sql      Tables, enums, indexes, helper functions
   │  ├─ 0002_rls_policies.sql     Row-Level Security for every table
   │  └─ 0003_storage_buckets.sql  product-images, tryon-assets, promo-banners, prescriptions
   └─ seed.sql                     Branches, categories, 3 placeholder products
```

## First-time setup

```bash
# 1. Install the Supabase CLI (https://supabase.com/docs/guides/cli)
brew install supabase/tap/supabase

# 2. From repo root:
cd Backend
supabase link --project-ref <hosted-project-ref>     # one-time
supabase db push                                     # applies migrations to hosted DB
supabase db reset --linked                           # nuke + re-run + seed (dev only!)

# 3. Locally:
supabase start                                       # boots Postgres + Studio at :54323
psql "postgresql://postgres:postgres@localhost:54322/postgres" -f seed.sql
```

## Roles & auth model

- **Customers** sign up via Supabase Auth (email/password initially; SMS OTP later via Africa's Talking). On first sign-up the app inserts a matching row into `public.customers` keyed on `auth.users.id`.
- **Super Admin** is a single Supabase user whose `user_metadata` JSON carries `{"role": "super_admin"}`. The `is_super_admin()` SQL helper reads this claim from the JWT. There is **no** branch-manager / staff tier in this SOW.
- **Service role** key (Daraja / Pesapal webhooks, SMS senders) bypasses RLS — used only server-side, never exposed to the browser.

## Payment webhooks

Daraja STK Push callback and Pesapal IPN are served from `/api/webhooks/{mpesa,pesapal}` in the Next.js app (Vercel serverless function). They write to `mpesa_transactions` / `pesapal_transactions` using the **service role** key, then attempt to match against `orders` by reference.

## Conventions

- All money columns are `numeric(10,2)` in **KES**. 16% VAT and 0 shipping by default; both configurable per order.
- Order numbers are human-readable (`OPX-2026-000123`) generated by `generate_order_number()`.
- Prescription files in Storage are namespaced by customer id: `prescriptions/<customer_id>/<filename>`. RLS uses `storage.foldername(name)[1]` to scope reads to the owner.
- Product search uses a stored `tsvector` column (`products.search_tsv`) with a GIN index — query via `to_tsquery('simple', $1)`.
